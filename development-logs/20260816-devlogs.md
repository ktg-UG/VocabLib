### 背景

Phase 7 の一括インポートを25語で dry-run した結果、**Gemini の無料枠を1回で使い切り**、
全件が2段目の Ollama（gemma3:4b）に落ちた。フォールバックの動作としては正しいが、
出力の品質に無視できない誤りがあった。

| 単語 | Ollamaの出力 | 正しい値 |
|---|---|---|
| `incorporation` | 組み入れる / **動詞** | 法人設立 / 名詞 |
| `resilience` | 回復力 / **形容詞** | 回復力 / 名詞 |
| `unanimously in favor of` | 全員一致して賛成 / **動詞** | 満場一致で〜に賛成して / 熟語 |

### 対応2: 和訳・品詞を直接指定できる書式を追加

入力ファイルにカンマ区切りの行を書くと、LLMを呼ばずにその値で登録する。

```
yield                          ← 従来どおりLLMが補完する
incorporation, 法人設立, 名詞     ← 書いたとおりに登録（LLMを呼ばない）
yield, 産出する                  ← 品詞は省略できる
```

- 品詞は9種の選択肢のみ受け付け、外れた値は**行番号付きでエラー**にして弾く
  （表記ゆれが1つ混ざると品詞フィルタが効かなくなるため）
- `--delay` はLLMを呼ぶ行の間だけ待つ（レート制限のための待機なので）

品詞の一覧は `ui/add_word_panel.POS_OPTIONS` にしか無く、`ui` より下の層から参照できなかった。
`db/store.py` に `PARTS_OF_SPEECH` として移し、プルダウンは `[POS_UNSET, *PARTS_OF_SPEECH]` で組む。

#### 注意点として気付いたこと

ローカルDBを削除すると `sync_state`（前回pullの時刻）も消えるため、
次の同期は**Supabaseの全行をpullする**。Supabase側を先に消しておかないと
テストデータがローカルに復活する。**削除は Supabase → ローカル の順**。

他品詞から補充される（12.10の仕様どおり）。語数が増えれば自然に解消する。
