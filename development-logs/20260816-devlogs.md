### Phase 8 の順序決定

残タスク（Web一覧・編集／ビジュアル刷新／タグ機能）のうち、**タグ機能**を先に選択。
根拠は `memo.txt` に開発者自身が書いた原則。

> スキーマに触るものはUIより先にやるべき
> （画面が増えてからデータ構造を変える方が高くつく）

Web の単語一覧を作ってからタグ列を足すと、画面・型・データ取得を作り直すことになる。

### 確定した仕様

| 論点 | 決定 |
|---|---|
| 個数 | 1単語につき1タグ |
| 持ち方 | `words.tag`（`text not null default ''`）。別テーブルにしない |
| 用途 | 出題の絞り込み / 一覧の分類。タグ別統計はやらない |
| 入力 | 英単語の入力欄に `incorporation #TOEIC` と書く |
| `#` 無しの場合 | 確認フォームの「修正」ボタンから入力 |
| 既存25語 | 全部に `TOEIC` を付ける |

**1語1タグにしたことで設計が大幅に単純化した。** カンマ区切りの分解も、
部分一致の誤ヒット対策（`,TOEIC,` を探す等）も、重複除去も不要になり、
検索は `WHERE tag = ?` で済む。

### 実装中に設計から変えた3点

1. **rumps の落とし穴**: `MenuItem` は最初に子を入れるまでサブメニュー（`_menu`）を
   持たず、`None` のまま。空の状態で `clear()` を呼ぶと落ちる。
   `if len(self.tag_item):` で守り、UIを起動せずサブメニューの構築・再構築を検証した。
2. **「タグが無いときサブメニューを隠す」を撤回**: 項目を動的に足し引きするより、
   常に出して中身を「すべて」だけにする方が単純で壊れにくい。
   代わりに、選択中のタグの単語が0になったら「すべて」に戻す
   （`list_tags()` は語数0のタグを返さないため、放置すると解除できない絞り込みが残る）。
3. **`set_word_tag()` は `synced_at` を NULL にしない**: 既存の更新系メソッドと同じく
   `updated_at` を進めるだけにした。`synced_at IS NULL OR updated_at > synced_at` に
   引っかかるので push される条件は満たす。1つのクラスに2通りのやり方を残さない。
