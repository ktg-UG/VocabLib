## 2. データ構造（8-1）

### 2-1. 列

```sql
-- SQLite（src/db/schema.sql）
tag TEXT NOT NULL DEFAULT ''
```

```sql
-- Postgres（src/db/supabase_schema.sql）
tag text not null default ''
```

`NULL` を使わず空文字を「タグなし」にする。`NULL` と `''` の2通りが同じ意味を持つと、
検索条件を毎回2つ書くことになるため。

### 2-2. なぜ別テーブルにしないか

同期のコストが理由。VocabLibは3テーブルを push / pull し、`words` は `updated_at` の
LWWで解決している。**列を1つ増やすだけなら、同期もRLSも1行も変わらない。**

別テーブルにすると、4つ目のテーブルに対して
「push / pull / 論理削除の墓標 / LWW / RLSポリシー」を新しく設計することになる。
1語1タグと決めた以上、多対多を表現する必要も無い。

### 2-3. 既存DBのマイグレーション

**このPhaseで一番壊しやすいところ。**

`schema.sql` は `CREATE TABLE IF NOT EXISTS` なので、**既に `words` が存在するDBには
何の効果もない**。列を書き足しただけでは、開発者の手元のDB（25語入り）に `tag` は生えない。
新規DBだけ動いて既存DBが `no such column: tag` で落ちる、という事故になる。

`Store._init_schema()` の後で、列の有無を見て足す。

```python
def _migrate(self) -> None:
    """スキーマ変更を既存DBに適用する。

    CREATE TABLE IF NOT EXISTS は既存テーブルには効かないため、
    列の追加はここで行う。何度実行しても安全（列があれば何もしない）。
    """
    columns = {row["name"] for row in self._conn.execute("PRAGMA table_info(words)")}
    if "tag" not in columns:
        self._conn.execute("ALTER TABLE words ADD COLUMN tag TEXT NOT NULL DEFAULT ''")
```

- `ALTER TABLE ADD COLUMN` は SQLite でも既存行に DEFAULT を埋めてくれる
- **べき等**にする（起動のたびに走るため）
- Supabase側は `alter table words add column if not exists tag text not null default '';`
  を `supabase_schema.sql` に追記する（SQL Editorで実行してもらう）

> 今後スキーマを変えるときも、必ずこの `_migrate()` に追記する。
> `schema.sql` だけ直すのは**新規インストールでしか動かない変更**になる。

## 3. 純粋関数と Store（8-2 / 8-3）

### 3-1. 置き場所: `src/tags.py`（新規）

タグの正規化と `#` 記法のパースは、**UIからもDB層からもインポータからも呼ぶ**。
`ui/` に置くと `rumps` / `AppKit` を巻き込んでテストできず、`db/store.py` に置くと
入力書式の話がデータアクセス層に混ざる。

`config.py` と同じ「どこからでも参照してよい最下層」として `src/tags.py` を新設する。
中身は**純粋関数だけ**（DBにもネットワークにも触らない）。

### 3-2. `normalize_tag()`

タグは人が手で打つので、放っておくと `TOEIC` / `TOEIC` / `#TOEIC` が別物になる。
保存する前に必ず通す。

```python
def normalize_tag(text: str | None) -> str:
    """タグを保存できる形に整える。空文字は「タグなし」を表す。

    - 前後の空白を除去する
    - 先頭の `#` を取る（入力欄で `#TOEIC` と書く記法に合わせるため）
    - 内側の空白は保つ（`TOEIC Part5` を1つのタグとして許す）
    - 大文字小文字は変換しない（表示にそのまま使うため）
    - カンマを除去する（インポータの区切り文字と衝突するため）
    """
```

大文字小文字を潰さない代わりに、**同一視もしない**。`toeic` と `TOEIC` は別タグになる。
メニューから既存タグを選べる（4-2）ので、手で打ち直す機会自体が少ない。

### 3-3. `parse_word_input()`

英単語の入力欄に書かれた `incorporation #TOEIC` を分解する。

```python
def parse_word_input(text: str) -> tuple[str, str]:
    """英単語の入力を (英単語, タグ) に分ける。

    >>> parse_word_input("incorporation #TOEIC")
    ('incorporation', 'TOEIC')
    >>> parse_word_input("extend an invitation to")
    ('extend an invitation to', '')
    """
```

- **最初の `#` で1回だけ分割する**。英単語側に空白を含むフレーズがあるので、
  空白ではなく `#` を境目にする
- `#` が無ければタグは空文字
- `#` 以降を `normalize_tag()` に通す（`# TOEIC` のような書き方も拾える）
- `#` だけ書いてタグ名が無い場合はタグなし扱い

### 3-4. `Store` のAPI

```python
def add_word(self, english, japanese, part_of_speech=None, tag="") -> str
def set_word_tag(self, word_id: str, tag: str) -> None
def list_tags(self) -> list[dict]        # [{"tag": "TOEIC", "count": 25}, ...] 件数の多い順
def get_next_word(self, tag: str | None = None) -> Word | None
```

- `Word` データクラスに `tag: str = ""` を足す
- `set_word_tag()` は他の更新系と同じく `updated_at` を進める。これで
  `synced_at IS NULL OR updated_at > synced_at` に引っかかり次の同期でpushされる
  （**忘れると同期されない**）
- 絞り込みは `WHERE deleted = 0 AND tag = ?` だけ。1語1タグなので部分一致の心配が無い
- `list_tags()` はタグなし（`''`）を除く

**誤答の選択肢はタグで絞らない。** 絞ると選択肢の在庫が枯れて
「同じ4語がいつも並ぶ」状態になり、綴りではなく位置で覚えてしまう。
誤答に必要なのは品詞が揃っていること（Phase 7）で、分野が同じである必要はない。

### 3-5. 絞り込みで単語が0件のとき

`get_next_word(tag)` が `None` を返す。UI側は
「タグ『◯◯』に出題できる単語がありません」と出し、**絞り込みを勝手に解除しない**
（勝手に別の単語を出すと、設定が効いていないように見えるため）。

## 4. Mac側のUI（8-4 / 8-5）

SPEC 1.4 の原則（Macは登録・出題・統計の数値確認のみ、操作は簡単に）を守る。
**タグの一括編集や整理はWebに置く。Mac側は「付ける」と「絞る」だけ。**

### 4-1. 登録フロー

```
[1] 「追加する英単語を入力してください」
        incorporation #TOEIC          ← タグまで一息で書ける
        ↓  parse_word_input()
[2] 確認フォーム（オートフィルの結果が入る）
        英単語   incorporation           [修正]
        和訳     法人設立、組み入れ         [修正]
        品詞     [ 名詞          ▼ ]
        タグ     TOEIC                   [修正]   ← 追加
                              [キャンセル] [保存]
```

`#` を書かなかった場合、タグ欄は `（なし）` と表示される。
**必要なときだけ「修正」を押して入力する**（押した時点で `（なし）` は消える）。

これは Phase 3 で確定した方針
（「修正することの方が少ないから通常はテキスト表示、直したいときだけ修正ボタン」）を
タグ欄にもそのまま適用したもの。他の項目と操作が揃う。

- タグ欄はオートフィルの対象にしない。タグは本人の分類であって、LLMが決めるものではない
- 「修正」を押したときの入力欄には、**既存タグを選べる補助は付けない**（Phase 8 では簡素に）

> **前回タグの自動プリセットは見送る。** 連続登録では楽だが、
> `#` を書き忘れた単語に前回の分野が黙って付く。
> 1語1タグなので誤ったタグは上書きでしか直せず、**間違いに気付けない方が高くつく**。
> 明示的に書いたものだけが付く、という規則にする。

### 4-2. 「出題するタグ」の切替（8-5）

メニューバーにサブメニューを1つ足す。

```
VocabLib
  次の問題を表示
  自動出題: ON
  ─────────────
  出題するタグ  ▸  ✓ すべて（25語）
                    TOEIC（25語）
                    ビジネス（8語）
  ─────────────
  単語を追加...
  単語一覧...
  統計...
```

- 選択中の項目にチェックマークを付ける
- 各タグの語数を併記する（0語のタグを選んで空振りするのを防ぐ）
- 選択状態は `sync_state` に `quiz_tag_filter` として保存し、**再起動後も維持する**
  （専用テーブルを作らない。キーバリューが要るのはこれだけ）
- 単語を登録したり同期でpullしたりしてタグが増減したら、メニューを組み直す
- **選択中のタグの単語が1語も無くなったら「すべて」に戻す。**
  `list_tags()` は語数0のタグを返さないため、そのタグはメニューから消える。
  選べない絞り込みが残ると「単語がありません」と言われ続けて解除もできない
- タグが1つも無いうちもサブメニューは出す（中身は「すべて」だけ）。
  項目を動的に足し引きするより単純で、壊れにくい

> **実装時に判明**: rumps の `MenuItem` は最初に子を入れるまでサブメニューを持たないため、
> 空の状態で `clear()` を呼ぶと `None` を触って落ちる。件数を見てから呼ぶこと。

## 5. 一括インポート（8-6）

### 5-1. 4列目としてのタグ

```
incorporation, 法人設立, 名詞, TOEIC
yield, 産出する、もたらす, 動詞, TOEIC
```

1語1タグなので4列目は1つだけ。5列目以降は無視する。

英単語欄の `#` 記法もここで使える（`incorporation #TOEIC` の1列だけの行）。
書式が2通りあると混乱するので、**4列目があればそちらを優先**する。

### 5-2. `--tag` オプション

```bash
uv run python -m src.tools.import_words tmp.txt --tag TOEIC
```

ファイル内で指定が無い行に、共通のタグを付ける。行に4列目があればそちらを優先する。

### 5-3. 登録済みの単語にタグを付ける（`--retag`）

**今回の「既存25語に全部 TOEIC を付ける」はこれで行う。**

```bash
uv run python -m src.tools.import_words tmp.txt --tag TOEIC --retag
```

- 通常は登録済みの単語を skip するが、`--retag` を付けると
  **skip せずタグを見る**（和訳・品詞・例文は触らない）
- **既にタグが付いている単語は上書きしない。** 1語1タグなので上書きは前のタグの消滅を意味し、
  Webや `#` 記法で付けたタグをインポータが黙って消すことになる。
  付け替えたいときは1語ずつ直す（Phase 9 のWeb編集で楽になる）
- タグが空の単語にだけ付ける。何度実行しても結果が変わらない

> SQLiteを直接 `UPDATE` しない。`updated_at` と `synced_at` の更新を書き忘れて
> **Supabaseに反映されないローカル変更**を作ってしまうため、必ず `Store` 経由にする。

### 5-4. 出力

```
インポート: tmp.txt（25語 / うちLLM補完 0語）

[1/25] be indicative of … skip（登録済み）→ タグ付与: TOEIC
[2/25] yield … skip（登録済み）→ タグ付与: TOEIC
...

  登録        0語
  タグ付与   25語
  skip        0語
  失敗        0語
```

`ImportResult` に `retagged` を足す。

## 8. 完了の定義（DoD）

`uv run pytest` が通ることに加え、以下を手動で確認する。

### データ

1. 既存DB（25語）でアプリを起動しても落ちず、`tag` 列が生えている

11. 4択の誤答は**タグを跨いで**選ばれている（品詞は揃っている）
