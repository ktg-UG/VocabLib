- 作成日: 2026-08-15
- 対象機能: F-09 単語追加フォームのUI刷新
- 前提: `design-docs/20260815/02-llm.md` のオートフィル（`LLMClient.lookup_word`）は実装済み・動作確認済み

---

## 1. なぜ変えるか

現行は `rumps.Window` を3回続けて出している（英単語 → 和訳 → 品詞）。
実際に使って2つ問題が出た。

| 問題                                       | 中身                                                                                                               |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| **修正しないのに毎回入力させられる** | オートフィルの結果はたいてい正しい。それでも3回ダイアログを踏む必要がある                                          |
| **UIが固まる**                       | `rumps.Window` はモーダルでメインスレッドを止める。その合間にLLMを呼ぶため、待ち時間がそのまま操作不能時間になる |

2つ目は `design-docs/20260815/02-llm.md` 6-2 で「割り切り」として許容したものだが、
1つ目を直すために自前フォームを作るなら、同時に解消できる。

---

## 2. 変更後の流れ

```
メニュー「単語を追加...」
   ↓
[1] rumps.Window で英単語だけ聞く（ここは現行のまま。単純で確実）
   ↓
[2] AddWordPanel を即座に開く
      英単語  postpone       [修正]
      和訳    取得中...              ← LLM待ち。UIは固まらない
      品詞    [（未設定）▾]          ← 取得までは無効化
                        [キャンセル] [保存]
   ↓ ワーカースレッドで lookup_word()
[3] 取得完了 → callAfter で流し込む
      和訳    延期する       [修正]
      品詞    [動詞 ▾]
   ↓
[4] そのままで良ければ [保存] を1回押すだけ
```

**修正しないなら操作は「保存」の1クリック。** これが今回の主目的。

## 3. UI設計

### 3-1. レイアウト（幅380 × 高さ190）

```
┌──────────────────────────────────────┐
│ 単語を追加                            │
│                                      │
│ 英単語   postpone            [修正]   │
│ 和訳     延期する            [修正]   │
│ 品詞     [動詞          ▾]           │
│                                      │
│                  [キャンセル] [保存]  │
└──────────────────────────────────────┘
```

### 3-2. 「修正」ボタンの実現方法

**表示用ラベルと入力欄を別ウィジェットにしない。**
`NSTextField` を1つ置き、編集可否を切り替えるだけにする。

| 状態                 | `setEditable_` | `setBezeled_` | `setDrawsBackground_` |
| -------------------- | ---------------- | --------------- | ----------------------- |
| 通常（テキスト表示） | False            | False           | False                   |
| 「修正」押下後       | True             | True            | True                    |

こうすると、見た目は「ただの文字」から「入力欄」に変わり、実体は同じオブジェクトなので
保存時は常に `stringValue()` を読むだけで済む。分岐が要らない。

押下後は `panel.makeFirstResponder_(field)` でカーソルを入れる。

### 3-3. 品詞はプルダウン（`NSPopUpButton`）

自由入力だと表記ゆれ（動詞 / 他動詞 / 【動】…）が起きて、
将来の集計・フィルタが効かなくなる。選択肢を固定する。

```
（未設定） / 名詞 / 動詞 / 形容詞 / 副詞 / 前置詞 / 接続詞 / 代名詞 / 間投詞 / 熟語
```

- 既定は「（未設定）」。保存時は `None` として扱う（`part_of_speech` はNULL許容）
- LLMが返した品詞がリストに無ければ「（未設定）」のまま
  （`llm/client.py` の `_lookup_prompt` はこのリストから選ぶよう指示済み）
- 品詞は「修正」ボタンを付けない。プルダウンは常に操作可能で十分

## 4. 実装

### 4-1. 新規ファイル `src/ui/add_word_panel.py`

```python
class AddWordPanel:
    def __init__(self, english: str,
                 on_save: Callable[[str, str, str | None], None],
                 on_close: Callable[[], None]): ...
    def show(self) -> None: ...
    def set_autofill(self, info: WordInfo | None) -> None: ...   # メインスレッドから呼ぶ
    def close(self) -> None: ...
```

- `panel.py` と同様、`_AddWordDelegate(NSObject)` がボタンの target と
  ウィンドウの delegate を兼ねる（素のPythonクラスは target になれないため）
- delegate の参照はパネル側で保持する（GCされるとクリックが効かなくなる）
- タイトルバーの × でも `on_close` が呼ばれるよう `windowWillClose_` を受ける
  （Phase 2 で `QuizPanel` に入れたのと同じ対策）

保存はパネル内では行わない。`on_save(english, japanese, part_of_speech)` を呼び、
DB書き込みと重複エラーの扱いは呼び出し側（`dialogs.py`）に任せる。
**パネルはUIだけ**という Phase 2 からの方針を維持する。

### 4-2. `src/ui/dialogs.py` の変更

`prompt_add_word()` を書き換える。

1. `_ask()` で英単語を聞く（現行のまま）
2. `AddWordPanel` を生成して `show()`
3. `threading.Thread` で `llm.lookup_word()` → `callAfter(panel.set_autofill, info)`
4. `on_save` で `store.add_word()`。`DuplicateWordError` はアラートを出してパネルを閉じない
   （英単語を直して再保存できるようにするため）

### 4-3. `src/ui/menubar.py` の変更

- 追加フォームを開いている間はクイズを出さない
  （フォームの上にクイズパネルが重なると操作不能になりうるため）
- フォームが閉じたら統計表示を更新する

## 5. これで解消されること

| 変更前                       | 変更後                                     |
| ---------------------------- | ------------------------------------------ |
| ダイアログ3回                | フォーム1枚 + 保存1クリック                |
| LLM待ちの間UIが固まる        | ワーカースレッド。待っている間も操作できる |
| 品詞は自由入力（表記ゆれ）   | プルダウンで固定                           |
| 修正するには必ず入力欄を通る | 修正が必要な項目だけ「修正」を押す         |

`config.AUTOFILL_TIMEOUT_SECONDS` は10秒のまま据え置く。
UIを止めなくなったので上限を縮める理由が無くなり、むしろGeminiの下限（10秒）を
下回れないという制約だけが残るため。

## 6. 完了の定義（DoD）

`uv run pytest` が通ることに加え、以下を手動で確認する。

1. 「単語を追加...」→ 英単語を入力 → フォームが**すぐ**開き、和訳が「取得中...」になる
2. 数秒後に和訳と品詞が埋まる。**この間もメニューバーが操作できる**
3. 何も直さず「保存」を押すだけで登録される
4. 「修正」を押すと該当欄が入力可能になり、直した内容で保存される
5. 品詞プルダウンで別の品詞を選んで保存できる
6. 既に登録済みの単語を保存 → 重複アラートが出て、**フォームは開いたまま**英単語を直して再保存できる
7. 「キャンセル」およびタイトルバーの × で閉じられる（どちらも登録されない）
8. LLMを全て無効にしても、空欄のフォームから手入力で登録できる

確認結果は `development-logs/20260815-devlogs.md` に記録する。
