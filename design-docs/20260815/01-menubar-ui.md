## 2. モジュール構成

```
src/
├── config.py          設定値（.env読み込み、DBパス解決）
├── quiz.py            出題データの組み立て ← UIに依存しない = テストできる
├── main.py            エントリポイント
├── db/                （Phase 1 完了済み）
├── srs/               （Phase 1 完了済み）
└── ui/
    ├── __init__.py
    ├── menubar.py     rumps.App サブクラス。タイマーとメニュー
    ├── panel.py       NSPanelによるクイズ表示
    └── dialogs.py     単語登録・統計表示のダイアログ
```

### 設計の要点: 「UIに依存しない層」を切り出す

v1 は出題ロジックが `ollama_client.py` と `app.py` に混ざっていて、**テストするにはメニューバーアプリを起動するしかなかった**。

v2 は `src/quiz.py` を挟む。

```
Store（データ） → quiz.py（何を出すか決める） → ui/（どう見せるか）
                  ↑ ここまでは純粋なPython = pytestで検証できる
```

`quiz.py` は `rumps` も `AppKit` も import しない。これが守られている限り、出題ロジックはCIでも検証できる。

## 3. 各モジュールの設計

### 3-1. `src/config.py`

```python
# 想定する内容（イメージ）
DB_PATH: Path              # 既定 ~/Library/Application Support/VocabLib/vocablib.db
QUIZ_INTERVAL_MINUTES: int # 既定 5
CHOICE_COUNT: int          # 既定 4
AUTO_START_QUIZ: bool      # 既定 True
```

- `.env` を `python-dotenv` で読む。値が無ければ上記の既定値。
- `VOCABLIB_DB_PATH` を環境変数で上書きできるようにする（開発時に本番DBを汚さないため）。
- v1 の `config.py` にあった PyInstaller 対応（`sys.frozen` / `sys._MEIPASS` 分岐）は、`.app` 化を決めるまで入れない。**必要になってから足す。**

### 3-2. `src/quiz.py`

出題1問ぶんのデータを組み立てる。

```python
@dataclass(frozen=True)
class Quiz:
    word: Word            # 出題対象
    choices: list[str]    # 4つの和訳（シャッフル済み）
    correct_index: int    # choices の中の正解位置

def build_quiz(store: Store, choice_count: int = 4) -> Quiz | None:
    """次に出す単語を選び、4択を組み立てる。単語が無ければ None"""
```

処理:

1. `store.get_next_word()` で出題単語を得る（None なら None を返す）
2. `store.get_distractor_meanings(word.id, limit=choice_count - 1)` で誤答候補を得る
3. 正解の和訳 + 誤答候補をシャッフルし、`correct_index` を確定させる

**登録単語が4個未満のときは選択肢が4つ揃わない。** その場合は集まった数だけで出題する（2択でも成立させる）。エラーにはしない。

> 誤答候補をLLMで生成する案は Phase 3 で検討する。`build_quiz` の中だけを差し替えれば済むよう、UI側は `Quiz` しか知らない設計にしておく。

### 3-3. `src/ui/panel.py`

v1 の `_show_quiz_panel` / `_expand_panel_with_example` を、**`VocabLibApp` から切り離した独立クラス**にする。

```python
class QuizPanel:
    def __init__(self, quiz: Quiz, on_answer: Callable[[bool], None],
                 on_close: Callable[[], None]): ...
    def show(self) -> None: ...
    def close(self) -> None: ...
```

- 画面右下に `NSPanel`（`NSFloatingWindowLevel`）で表示。位置・サイズは v1 を踏襲（340 × 200、右下から16pxマージン）。
- 選択肢はボタン。押すと ✅/❌ を色付きで表示し、`on_answer(is_correct)` を呼ぶ。
- 正解: 1秒後に自動クローズ（v1 と同じ `callLater`）。
- 不正解: パネルを上方向に80px拡張して例文エリアを出す。**Phase 2 では `word.example_sentence` があれば表示、無ければ「例文なし」**。Phase 3 でここにLLM生成を差し込む。
- 「閉じる」ボタン、またはフォーカスが外れたらクローズ → `on_close()`。

v1 の `_make_label` の `multiline` 対応（`setUsesSingleLineMode_(False)` + `cell().setWraps_(True)`）は**そのまま移植する**。これが無いと例文の2行目（和訳）が切れる、という既知の落とし穴が解決済みのコードなので。

### 3-4. `src/ui/menubar.py`

```python
class VocabLibApp(rumps.App):
    # メニュー構成
    #   今すぐ出題
    #   ─────────
    #   自動出題: 4分32秒後      ← クリックでオン/オフ
    #   ─────────
    #   単語を追加...
    #   単語一覧...
    #   ─────────
    #   統計...
    #   通算: 128問 82.0%        ← 表示のみ
    #   連続 5日 / 復習待ち 12
    #   ─────────
    #   終了
```

- `rumps.Timer` を1秒間隔で回し、残り秒数をメニュータイトルに反映（v1 と同じ）。0になったら出題。
- 統計行は**アプリ起動時と回答後に `store` から読み直す**。メモリ上のカウンタは持たない。

## 4. v1 のバグ・問題点と、v2 での対処

Phase 2 は v1 の `app.py` を作り直すPhaseなので、v1 で踏んだ地雷を明示的に潰す。

| # | v1 の問題                                                                                                                     | v2 の対処                                                                                              |
| - | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 1 | 統計を`self.stats` のdictで持っており、**アプリ再起動で消える**                                                       | `store.get_stats_overall()` を都度読む。UIは統計を保持しない                                         |
| 2 | 回答を`self._pending_record` に溜め、**パネルを閉じた時に初めて保存**。閉じる前にアプリが落ちると回答が消える         | ボタンを押した瞬間に`store.record_answer()` を呼ぶ。SQLiteへの書き込みは数ミリ秒なのでUIは止まらない |
| 3 | `_show_quiz` のバックグラウンド処理が失敗すると `return` するだけで、**タイマーが再開されず自動出題が黙って止まる** | 出題の成否にかかわらず、必ず`finally` 相当でタイマーを再開する                                       |
| 4 | `rumps.MenuItem(callback=...)` と `@rumps.clicked(...)` デコレータで**同じメソッドを二重登録**                      | デコレータを使わず`MenuItem(callback=...)` に統一する                                                |
| 5 | シート全体を毎回フェッチしてから1件選ぶ（N+1的な非効率）                                                                      | `store.get_next_word()` が SQL 1本で1件だけ返す（Phase 1で解決済み）                                 |
| 6 | 単語登録機能がなく、**スプレッドシートを直接開いて手入力**する必要があった                                              | 「単語を追加...」ダイアログを実装（2-5）                                                               |

### 4-1. スレッドの扱い（v1から踏襲する規約）

v1 で正しく機能していた `threading.Thread` + `AppHelper.callAfter` のパターンは v2 でも使う。ただしルールを明文化する。

> **DBアクセス・ネットワークはワーカースレッド。UI操作は必ず `callAfter` でメインスレッドに戻す。**

- `Store` は接続1本を `Lock` で保護しているのでスレッドから呼んで安全（Phase 1で対応済み）。
- Phase 2 の時点では DB アクセスは十分速いため、**回答記録は同期的に呼んでよい**。ワーカースレッドが必須になるのは Phase 3（LLM、数秒かかる）から。ただし呼び出し箇所は最初から差し替えやすい形にしておく。

## 5. 画面と状態遷移

```
           起動
            ↓
    ┌─→ 待機（タイマー稼働、残り秒数をメニュー表示）
    │       ↓ 残り0秒 / 「今すぐ出題」
    │   build_quiz()
    │       ├─ None（単語0件）→ 通知「単語を追加してください」→ 待機へ
    │       ↓
    │   パネル表示（4択）
    │       ↓ ボタン押下
    │   record_answer() を即実行 + ✅/❌表示
    │       ├─ 正解 → 1秒後に自動クローズ
    │       └─ 不正解 → 例文エリアを展開 → 「閉じる」or フォーカス喪失でクローズ
    │       ↓
    └── タイマー再開
```

## 6. 単語登録ダイアログ（2-5）

`rumps.Window` を使う。

- 入力: 英単語 / 和訳 / 品詞（任意）
- `store.add_word()` を呼ぶ
- `DuplicateWordError` → 「既に登録されています」を `rumps.alert` で表示
- `ValueError`（空文字）→ 「英単語と和訳は必須です」

> Phase 3 で、英単語を入力した時点で和訳・品詞をLLMが自動入力する（SPEC.md 11節の確定事項）。
> `rumps.Window` は単一テキストフィールドしか持たないため、3項目を扱うには
> **改行区切りで入力させる簡易版**か**`NSPanel` で自前のフォームを作る**かの選択になる。
> Phase 2 では簡易版（`rumps.Window` に「英単語」「和訳」を順に聞く2ステップ）で実装し、
> Phase 3 でオートフィル対応のフォームに作り替える。

## 8. テスト方針（2-8）

**テストするのは `src/quiz.py` だけ。** `ui/` は自動テストしない。

理由: `rumps` / `AppKit` は実際にmacOSのイベントループを起動しないと動かず、自動テストの費用対効果が悪い。UIは手動での動作確認（DoD）で担保する。

`tests/test_quiz.py` で検証すること:

| テスト                           | 内容                                           |
| -------------------------------- | ---------------------------------------------- |
| 単語0件なら None を返す          | `build_quiz` の境界                          |
| 選択肢に正解の和訳が含まれる     | `choices[correct_index] == word.japanese`    |
| 選択肢に重複がない               | 誤答候補に正解と同じ和訳が混ざらない           |
| 単語が4件以上あれば選択肢は4つ   | 正常系                                         |
| 単語が2件しかなければ選択肢は2つ | 少数登録時に落ちないこと                       |
| 正解位置が固定されない           | 複数回生成して`correct_index` がばらけること |

## 10. 完了の定義（DoD）

`uv run pytest` が通ることに加え、**以下を手動で確認できて初めて「完了」**とする。

1. `uv run python -m src.main` でメニューバーにアイコンが出る
2. 「単語を追加...」で単語を3語以上登録でき、重複登録が弾かれる
3. 「今すぐ出題」でパネルが右下に出て、4択が表示される
4. 正解を選ぶと ✅ が出て1秒後に閉じる
5. 不正解を選ぶと ❌ と正解が表示され、パネルが下に伸びる
6. 「統計...」に回答数・正答率・連続日数が正しく出る
7. **アプリを終了して再起動しても統計が保持されている**（v1のバグの回帰確認）
8. 自動出題をオンにし、間隔を1分に縮めて2回連続で出題されること（タイマーが止まらない = v1問題#3の回帰確認）

確認結果（成功/失敗）は `development-logs/20260815-devlogs.md` に記録する。
