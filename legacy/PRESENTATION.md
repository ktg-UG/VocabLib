# VocabLib — 技術説明

> PC作業中に英単語が自動で問われる、macOS メニューバー常駐の反復学習アプリ
> （デモでご覧いただいた通り、作業を止めずに「意思に頼らず」単語と向き合わせる仕組みです）

---

## 1. 使用した技術

| カテゴリ | 技術 | 選定理由 |
|---|---|---|
| 言語 | Python 3.12 | 実装速度と AI/API ライブラリの豊富さ |
| ネイティブ UI | rumps + PyObjC（`NSPanel` / `NSNotificationCenter`） | メニューバー常駐と「作業を邪魔しない」UI を実現 |
| AI（選択肢・例文生成） | ローカル LLM **Ollama**（`gemma3:4b`） | コスト0・オフライン動作・学習データを外に出さない |
| 外部 API | **Google Sheets API v4**（OAuth 2.0） | 単語帳と学習履歴を"普段のエディタで編集できる"形で管理 |
| 反復アルゴリズム | **SM-2（SuperMemo 2）** を自前実装 | 忘却曲線に基づく最適な復習間隔の自動制御 |
| 配布 | PyInstaller（`.app` バンドル、`LSUIElement`） | Dock 非表示のネイティブアプリとして配布 |

> **AIの使いどころ**：正誤判定や単語選択は「決定的な処理」に任せ、AIは**人間の判断力が要る2箇所**に絞って使っています。①**4択の誤答選択肢の生成**（正解と同じ意味領域の"紛らわしい"選択肢を作る＝学習効果を高める）、②**不正解時の記憶に残る例文生成**。LLM出力は完璧でないため、同義語禁止のプロンプト制約・重複除去・フォールバックで品質を担保しています。

## 2. アーキテクチャ（データフロー）

```
┌─────────────────────────────┐
│ メニューバー (rumps)         │  ← 5分間隔のタイマー / 「今すぐクイズ」
└──────────────┬──────────────┘
               ▼
┌─────────────────────────────┐      ┌────────────────────┐
│ SM-2 スケジューラ            │◀────│ Google Sheets v4   │
│  次に出す単語を決定          │ 単語 │  単語帳＋学習履歴  │
└──────────────┬──────────────┘      └────────────────────┘
               ▼  別スレッド（UIをブロックしない）
┌─────────────────────────────┐      ┌────────────────────┐
│ Ollama (localhost:11434)     │◀────│ ローカル LLM        │
│  ① 4択の誤答選択肢を生成     │      │  (gemma3:4b)        │
│  ② 不正解時に例文を生成      │      │  失敗時→ローカル生成 │
└──────────────┬──────────────┘      └────────────────────┘
               ▼  callAfter → メインスレッドで UI 更新
┌─────────────────────────────┐
│ クイズパネル (PyObjC NSPanel)│  ← 4択 UI・フォーカスを奪わない
└──────────────┬──────────────┘
               ▼
        回答 → 例文表示 ＋ Sheets に学習履歴/例文を書き戻し
```

**責務を4層に分離**：スケジューラ / UI / AI / 永続化。各層が疎結合なので、AI層が落ちても他は動き続けます。

## 3. 直面した課題と解決策

### 課題① LLMの応答を待つと、UIが固まる

- 4択の選択肢生成・例文生成は Ollama への HTTP リクエストを伴う
- **解決**：`threading.Thread` でバックグラウンド生成し、**UIをブロックしない**。例文は生成中に「💡 例文を生成中...」を表示、結果は Sheets にキャッシュ → **2回目以降は即時表示**

### 課題② PyObjC はメインスレッド外から UI を触れない

- 別スレッドで生成した選択肢・例文を、そのままではパネルに反映できない（クラッシュ）
- **解決**：`PyObjCTools.AppHelper.callAfter` で **UI更新だけをメインスレッドに委譲**。生成（重い処理）と描画（メインスレッド）を明確に分離

### 課題③ AI に依存すると、AIが死ぬとアプリが死ぬ

- Ollama 未起動・停止・生成失敗時に機能全体が止まるのは避けたい
- **解決**：選択肢は**ローカル生成にフォールバック**、例文は `"word" means "meaning"` に自動切り替え。**LLMに依存しない動作を保証**（＝落ちない設計）

### 課題④ LLMの選択肢が、たまに正解の"言い換え"になり問題が破綻する

- 例：正解「生み出す」に対し「作り出す」を誤答に出す等
- **解決**：プロンプトで**同義語・言い換えを明示的に禁止** ＋ 重複除去。それでも失敗すればローカル生成へフォールバック

### 課題⑤ ランダム出題では反復が非効率

- **解決**：SM-2 を実装。正解で復習間隔を指数的に延ばし（1日→6日→前回×難易度係数）、**不正解は5分後に再出題**。苦手な単語ほど短い間隔で繰り返し触れられる

## 4. 成果と今後の展望

### 成果

- **約1ヶ月**で、要件定義 → 設計 → 実装 → `.app` 配布まで**個人で完遂**
- 単語帳を Google Sheets に置くことで、**外部アプリ不要で追加・編集**できる UX
- 自分自身が**日次で運用（ドッグフーディング）** し続けている実用ツール

### 今後の展望

- **選択肢生成の品質向上**：モデルの大型化やFew-shot例の追加で"言い換え誤答"をさらに削減
- **クラウド/ローカル LLM の切り替え**：品質を求める場面ではクラウド、日常はローカル
- **学習の可視化**：正答率・忘却曲線の推移をダッシュボード化
- **多言語・複数デバイス対応**
